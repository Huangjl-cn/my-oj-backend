# 代码沙箱统一执行接口适配任务

请检查当前代码沙箱项目，并按下面的后端调用契约完成必要调整。目标是让真实 Docker 执行覆盖所有支持语言，不再使用 AI 根据输入猜测输出。先阅读现有控制器、工厂、执行模板和响应模型；只修改契约不一致的部分。

## HTTP 契约

- 后端对所有语言统一调用 `POST /executeCode`，不再请求 `/executeCodeByAI`。
- 请求头包含 `auth: secretKey`。
- JSON 请求结构：

```json
{
  "inputList": ["1 2", "3 4"],
  "code": "用户代码",
  "language": "java"
}
```

- `language` 只接受 `java`、`cpp`、`go`、`python`、`javascript`。统一入口应通过现有工厂/注册表选择相应 Docker 执行实现。
- 响应结构保持如下，不要新增或重命名字段：

```json
{
  "outputList": ["3", "7"],
  "message": "接口执行说明",
  "status": 1,
  "judgeInfo": {
    "message": "Accepted",
    "memory": 1024,
    "time": 20
  }
}
```

## 状态与消息语义

- `status`: `1` 执行成功、`2` 编译错误、`3` 运行错误、`4` 沙箱系统错误。
- `outputList` 必须与 `inputList` 顺序一致，每个输入对应一个输出；禁止使用 AI 生成、推测或修正输出。
- `ExecuteCodeResponse.message` 只描述沙箱接口/执行流程状态。
- 当 `status` 为 `2`、`3` 或 `4` 时，把可返回给用户的编译器输出、stderr 或堆栈放入 `judgeInfo.message`。建议保留稳定的错误类型首行，例如 `Compile Error` 或 `Runtime Error`，后接原始诊断；不得只返回笼统错误文字。
- `judgeInfo.memory` 单位为 KB，`judgeInfo.time` 单位为 ms。保留项目当前对多个用例的资源聚合规则，但要保证单位正确。

## 执行与资源要求

1. `/executeCode` 必须按语言进入真实、隔离的 Docker 执行器，并继续执行已有的危险操作、进程、网络和文件系统限制。
2. 删除 `/executeCodeByAI` 及其仅为 AI 推断输出服务的调用链；若发现其他真实调用方，先说明影响再决定是否保留兼容入口。
3. 后端 HTTP 超时为 `30000 ms`。沙箱自身应有更短且明确的编译/运行超时，并在可控情况下返回结构化错误，避免连接无期限占用。
4. 最终题目时间和内存判定由后端完成；当前请求不携带题目限制。若沙箱存在固定容器硬上限，检查它不会在合理的后端判题阈值之前误杀运行时较重的语言。
5. 不改变鉴权方式、字段结构或状态码含义，不做无关重构。

## 验收标准

- 五种语言分别有 `/executeCode` 路由/工厂分发测试，且测试断言真实执行器被选择。
- 覆盖成功、编译错误、运行错误、系统错误和超时；错误测试断言 `judgeInfo.message` 包含有效诊断。
- 覆盖多个输入时输出数量和顺序正确，内存为 KB、时间为 ms。
- 仓库中不再有实际使用 `/executeCodeByAI` 或 AI 推断输出的代码。
- 最后说明修改文件、接口兼容性和运行过的测试命令。
